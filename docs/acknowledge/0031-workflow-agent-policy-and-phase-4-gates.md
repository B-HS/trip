# ADR-0031 — 에이전트 운용은 Workflow 로만, 모델 배분과 4단계 검증·push 시점 (2026-09-09)

## 배경

세션 3 시작 시 사용자가 에이전트 운용 규칙을 바꿨다: Workflow 를 적극 사용하고, 구현·리서치·리뷰는 메인 모델(Fable)이 아니라 Opus(max·high)와 Sonnet 을 적재적소에 쓰며, 서브에이전트(`Agent` 도구) 직접 호출은 절대 금지한다. 컨텍스트 복원 후 확인 질문 4건에 전부 추천안으로 답했다.

## 결정

- **위임 경로**: `Agent` 도구는 호출하지 않는다. 조사·구현·리뷰 위임은 전부 `Workflow` 스크립트의 `agent()` 로 한다. 파일을 동시에 바꾸는 에이전트가 2개 이상일 때만 `isolation: 'worktree'` 를 쓰고, 결과는 `docs/PROCESS.md` 진행 메모의 patch 이식 절차로 합친다.
- **모델 배분**: 구현 = Opus `effort: 'max'`, 리뷰·검증 = Opus `effort: 'high'`, 리서치·API 사실 확인·문서 초안·단순 조사 = Sonnet(`medium`~`high`). 메인(Fable)은 지휘·ADR·재검증·핵심 결정·파괴적 변경(마이그레이션 적용, push·머지)만 직접 한다. 리서치는 주제당 질문 3개·10분 상한을 유지한다.
- **로드맵 7 완료 게이트**: ADR-0027 의 에디터는 게시글(`trip_post`) 용이라 로드맵 6 전에는 연결할 화면이 없다. 컴포넌트·서버 렌더·검증·테스트·`bun run build` 가 통과하면 화면 미연결 상태로 push·prod 머지한다(배포 영향 없음). 편집·YouTube 삽입·서버 sanitize 의 브라우저 실측(라이트·다크)은 로드맵 6 의 게시글 작성·상세 화면에서 수행하고 결과를 ADR-0027 에 추기한다.
- **자동 push**: `git config llm-rules.auto-push true` 로 기록해 ADR-0022 의 "단계 완료마다 자동 push·prod ff 머지" 와 가드 훅 설정을 일치시킨다(세션 3 에서 실행).
- **문서 헤더**: ARCHITECTURE·PROCESS·roadmap·data-model 의 "대응 커밋" 은 단계의 코드 커밋에서 함께 갱신한다. 별도 docs 커밋을 만들지 않는다.

## 이유

사용자 지시. Workflow 는 제어 흐름이 스크립트로 고정되어 병렬·검증 단계가 재현 가능하고, 모델 배분을 호출마다 명시할 수 있다. 로드맵 7 을 6 과 묶어 실측하면 게시판 골격을 앞당기거나 임시 라우트를 만드는 우회를 피한다.

## 기각된 대안

- Workflow 도 쓰지 않고 메인이 전부 직접: 사용량 과다(guidelines §12) 와 사용자 지시 위반.
- 로드맵 7 단독 실측을 위해 게시판 골격(마이그레이션 0006 일부)을 앞당기기: 마이그레이션이 둘로 갈라지고 6 의 설계(ADR-0028)를 반쯤 미리 확정하게 된다.
- 임시 검증 라우트: 우회(HACK) 금지 원칙 위반.
- `auto-push false` 유지: push 마다 승인 프롬프트가 떠 ADR-0022 와 어긋난다.

## 운용 메모 (2026-09-10)

- 로드맵 6 UI 는 워크트리 병렬 대신 **한 트리에서 순차 3단계**(공용 컴포넌트 → 프레임·홈·탐색·셸 → 게시판·프로필)로 돌렸다. 병렬로 나누면 공용 컴포넌트 계약을 두 에이전트가 각자 만들어 patch 이식 충돌이 나고, 워크트리는 스폰 시점의 HEAD 를 기준으로 삼아 커밋 전 산출물을 못 본다. 워크트리 병렬은 서로 파일 집합이 완전히 갈리는 작업에만 쓴다.
- 워크플로 실행 중 메인은 대기(`until` 루프 10분 단위)하며, Stop 훅의 typecheck 가 에이전트의 중간 상태에서 실패하면 워크플로 종료까지 턴을 유지한다.
- 실측 결과: Workflow A 49분·B 52분·C 34분·리서치 4분. 리뷰 렌즈 4개(security·convention·fsd·api) + Fix 1개 구성이 잘 맞았다.
